EasyXT

基于 MiniQMT 平台中的 xtquant 进行二次封装，提供统一接口、智能参数处理与完善的错误机制，让量化数据获取与交易更简单、更稳健。

功能亮点 安装配置 快速上手 常用API 架构设计
项目简介
位置：MiniQMT/xtquant/EasyXT 适配语言：Python 3.6~3.12 场景：数据获取 / 交易执行 / 事件回调
  • 统一 API：对 xtquant 的多模块进行统一命名与参数风格封装。
  • 智能参数：容错与默认值注入，减少样板代码。
  • 错误处理：分级异常与重试机制，保障线上稳定性。
  • 开发友好：更友好的返回结构与类型提示。
功能亮点
  • 行情数据：K线/分时/快照等统一接口，一键订阅与缓存。
  • 账户交易：下单、撤单、查询统一封装，支持风控钩子。
  • 事件回调：撮合/成交/资金变动事件集中式处理。
  • 日志与监控：可插拔日志适配器与性能指标采集。
  • 插件扩展：策略组件与数据管线可扩展。
安装与环境配置
pip install easyxt # 若发布为 pip 包；否则使用本地路径安装 # 本地开发（示例） # 假设 EasyXT 位于 MiniQMT 安装目录下的 xtquant/EasyXT # 例如：D:\QMT交易端\userdata_mini\xtquant\EasyXT import sys, os EASYXT_HOME = r"D:\QMT交易端\userdata_mini\xtquant\EasyXT" sys.path.append(EASYXT_HOME) # 环境变量（根据你的 MiniQMT 实际路径调整） os.environ['XTQUANT_HOME'] = r"D:\QMT交易端\userdata_mini" os.environ['PTRADE_HOME'] = r"C:\PTrade" # 如需对接 PTrade
快速上手：三行订阅与获取
from easyxt import Market, Trade, Events # 1) 订阅与拉取行情（自动处理市场/代码格式） df = Market.fetch_kline("SH.600000", period="1m", start="2024-10-01", end="2024-10-31", adjust="none") # 2) 下单示例（带风控与错误处理） order_id = Trade.buy("SH.600000", price=10.23, volume=100, account="模拟账户A") # 3) 事件回调（集中式） @Events.on("order_filled") def on_filled(event): print("成交回报：", event)
常用 API 一览

Market

  • fetch_kline(code, period, start, end, adjust)
  • fetch_snapshot(code) / fetch_ticks(code, start, end)
  • subscribe(codes, fields, on_update)
  • cache.enable(ttl) / cache.clear()

Trade

  • buy(code, price, volume, account)
  • sell(code, price, volume, account)
  • cancel(order_id)
  • query_orders() / query_positions() / query_assets()
  • set_risk_guard(guard_fn)

Events

  • on(event_name)(handler)
  • start() / stop()
  • supported(): ['order_filled','order_rejected','asset_changed','tick']

Utils

  • normalize_code("600000") -> "SH.600000"
  • retry(fn, times=3, backoff=0.5)
  • log.set_level("INFO") / log.bind(handler)
架构示意
EasyXT ├─ Market # 行情层：统一订阅/拉取/缓存 ├─ Trade # 交易层：下单/撤单/查询，风控钩子 ├─ Events # 事件层：集中式回调分发 ├─ Utils # 工具层：代码归一化/重试/日志 └─ Adapters # 适配层：对接 xtquant 原始 API
对比与优势
  • 更少样板代码：参数与代码格式智能填充。
  • 更高健壮性：错误分级 + 重试回退策略。
  • 更易维护：统一命名 + 返回数据结构明确。
  • 可扩展：插件化组件，满足不同策略需求。
